# Platform Documentation

The Enterprise Data Simulator began as a retail data generator. P001 turned it
into a platform that retail happens to be the first tenant of. P001.1 refined
the extension points before the foundation was frozen. P002 added the execution
model that turns a domain's declarations into a validated plan. P003 gave a
simulated enterprise a durable identity and somewhere to record its progress.
P004 defined what time means inside a simulation. P005 bound the three
primitives into a single validated run, and P005.1 defined the vocabulary a
scheduler reports in. P006 is the scheduler, and P006.1 wired Retail into it
end to end. PADR-015 then made that wiring's one architectural consequence a
standing rule, and PADR-016 records what running a domain over simulated time
turned out to prove: that an enterprise's data is its state.

## Relationship to the feature ADRs

The two sets do not overlap and neither supersedes the other.

* **ADR-001 to ADR-012** answer *what the data means*: that money is copied
  from the checkout, that state changes go in history tables, that a completed
  feature is frozen. They are Retail's rules and they moved with Retail into
  `eds/domains/retail/`.
* **PADR-001 to PADR-005** answer *where code is allowed to live* and *what may
  depend on what*. They constrain every domain, including ones not yet written.

Where they meet: ADR-005 (deterministic generation) is the property PADR-005
(backward compatibility) is measured against. A refactor that changed one
generated byte would violate both.
