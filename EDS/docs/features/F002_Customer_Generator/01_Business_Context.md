# F002 – Customer Generator

**Feature ID:** F002

**Feature Name:** Customer Generator

**Priority:** Critical

**Status:** Complete

**Version:** 1.0

---

# Objective

Implement the Customer Generator module.

The generator creates the customer master datasets that will be consumed by
all future simulation features.

This feature generates only customer master data. It does not generate any
customer behaviour: no login history, browsing, orders, payments, sessions, or
events.

---

# Dependencies

Already implemented:

- F000 Repository Foundation
- F001 Master Data Generator

Consume the datasets generated by F001. Do not regenerate master data.

# Datasets

## Customers

`customer_id`, `customer_number`, `first_name`, `last_name`, `full_name`,
`gender`, `date_of_birth`, `email`, `phone`, `registration_date`, `status`,
`email_verified`, `mobile_verified`, `preferred_language`,
`preferred_currency`, `customer_segment`, `registration_source`,
`acquisition_channel`, `risk_score`, `lifecycle_stage`, `created_at`,
`updated_at`

## Customer Addresses

`address_id`, `customer_id`, `address_type`, `line1`, `line2`, `city_id`,
`state_id`, `country_id`, `postal_code`, `is_primary`, `latitude`,
`longitude`, `created_at`

Business rules:

- Every customer must have at least one address.
- A customer may have two addresses.
- Exactly one address must be primary.
- All city, state, and country IDs must exist.

## Customer Preferences

`preference_id`, `customer_id`, `email_opt_in`, `sms_opt_in`, `push_opt_in`,
`preferred_language`, `preferred_currency`, `timezone`

## Customer Loyalty

`loyalty_id`, `customer_id`, `loyalty_number`, `tier`, `points_balance`,
`enrollment_date`, `status`

# Distributions

| Dimension | Values |
| --- | --- |
| Segment | New 35%, Regular 40%, Premium 20%, VIP 5% |
| Account status | Active 94%, Inactive 3%, Suspended 2%, Closed 1% |
| Email verification | Verified 92%, Not verified 8% |
| Mobile verification | Verified 90%, Not verified 10% |
| Loyalty tier | Bronze 60%, Silver 25%, Gold 10%, Platinum 5% |

Registration sources: Web, Android App, iOS App, Partner Portal.

Acquisition channels: Organic Search, Paid Search, Social Media, Email
Campaign, Referral, Direct.

Risk score: 0–100, normal distribution, mean approximately 25, few high-risk
customers.

Registration date: realistic dates covering the previous five years. Older
customers should generally have higher loyalty points.

---

# Geography

Use the geography datasets generated in F001. Never invent countries, states,
or cities. Always reference existing master data.

---

# Data Quality Rules

- Email must be unique.
- Phone must be unique.
- Customer number must be unique.
- Customer ID must be unique.
- Every address must reference an existing city, state, and country.
- Exactly one primary address per customer.

---

# Validation

Validate duplicate emails, duplicate phones, duplicate customer numbers,
missing addresses, invalid foreign keys, more than one primary address,
customers without a preference record, and customers without a loyalty record.

---

# CLI

```bash
eds generate customers
eds generate customers --customers 1000 --seed 42
```

---

# Performance

Follow the architecture used in F001: Polars DataFrames, batch generation, no
Python object per customer, deterministic output from a random seed.

---

# Out of Scope

Customer login, browsing, search, wishlist, cart, orders, payments, sessions,
events, recommendations, and the fraud engine. These belong to future
features.

---

# Deliverables

Complete when all datasets are generated, validation passes, the CLI works,
unit tests pass, Ruff passes, MyPy passes, Parquet is exported, and output is
deterministic for a given seed.
